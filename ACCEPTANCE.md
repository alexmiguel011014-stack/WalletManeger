# wallet Manager — acceptance flows

This checklist applies to the local-ledger debug APK. New installs start without financial rows. The v3-to-v4 migration preserves an existing local ledger and display preferences while adding an empty import queue. Rico notification examples below are synthetic/redacted fixtures; they do not claim compatibility with live Rico notification formats.

| Flow | User action | Expected visible result | Empty/error and accessibility expectation |
| --- | --- | --- | --- |
| First launch | Open app, read disclosure, tap “Começar a cadastrar” | Dashboard opens without account, permission, or credential prompt; only built-in categories exist | On local-data failure, show a readable error, not a permanent spinner; wallet Manager symbol has a spoken label on welcome |
| Dashboard | Start empty, add income and expense in Extrato, return to Início | Balance is the net sum of all saved transactions; current-month income, expenses, recent rows and period update together | Empty state explains how to add a first transaction; currency is read as text and never conveyed only by color |
| Extrato | Add a transaction, search/filter, open details, edit then delete | Type, amount, date, category, merchant and description persist locally; edits update the same row | Invalid amount/date/category and empty merchant cannot save; no matches explains how to clear filters; row is a reachable touch target |
| Rico optional source | In Ajustes, choose Rico and tap the Android notification-access route. Optionally enter exactly four final digits only when the Rico notice visibly labels that account/card ending | The app shows Rico as the only supported source, its installed/permission state, and explains that Android permission is broad while wallet Manager reads only the selected package. A labeled nonmatching ending is discarded before the inbox | No permission prompt appears on first launch; a missing source, denied/revoked permission and no-source state have readable guidance. There is no bank API, Open Finance link, credential, app enumeration, or network action |
| Pending imports | From Extrato, open “Importações pendentes” and review synthetic fixtures: card bill paid, bakery R$ 8,89, a separate purchased part, and money received | Card-bill payment is a neutral acknowledgement; bakery and part remain separate expense drafts; money received remains an income draft. No balance or total changes until each applicable item is edited, categorized, and confirmed | Drafts contain fixed labels rather than notification text. Invalid edits cannot confirm; a duplicate warning requires explicit acknowledgement and never silently removes a valid purchase |
| Ignored/ambiguous notices | Use synthetic declined, pending, OTP, promotion, foreign-currency, missing-value, multiple-value, ambiguous-installment, and nonselected-feed messages | None reaches the pending inbox. A single amount explicitly marked as the current installment remains reviewable and never creates future rows | Raw notification title/body, codes, Pix keys, email, phone and full account/card identifiers are not stored or logged |
| Replay and shade dismissal | Redeliver the same notice, update/repost it, dismiss it in Android's notification shade, rapidly tap confirm twice, and create a manual collision after a draft exists | Exact replay creates at most one draft/ledger row; an updated/reposted notice is separately reviewable; shade dismissal does not erase a saved draft; a collision triggers an explicit duplicate acknowledgement before the ledger write | Drafts remain outside totals until one atomic confirmation succeeds; a valid repeated purchase is never silently discarded based only on date/value |
| Disconnect and reset imports | Disconnect Rico, choose to keep or discard pending drafts, then use “Excluir todos os dados” | Disconnect stops new capture. Kept drafts remain reachable for review; discarded drafts are removed. Existing confirmed transactions remain. Reset clears pending drafts and the app's selected source while retaining built-in categories and display preferences | The app explains that notification-access revocation itself happens in Android settings; unavailable/disabled permission and no-source states have readable guidance |
| Insight/alert | Add enough transactions to trigger a local rule, archive and re-open | Rule, source transaction IDs, local-data attribution, and reversible state are visible | Empty inbox explains that records are needed; severity has text, not color alone |
| Assistant | Ask about a month with data, then an empty month and an unsupported question | Supported answer uses deterministic local arithmetic and cites transaction IDs; empty data gives setup guidance; unsupported answer states limitation | Blank prompt cannot send; conversation order and roles are spoken |
| Budget | Open “Planos”, create a category limit, edit it and save | Current-month category spending and overage state update | No budget prompts category selection; invalid/negative/overlarge amounts cannot save; warning is a text label plus progress |
| Delete local data | Open “Ajustes”, cancel once, then confirm deletion | Cancel leaves local rows intact; confirm clears financial records and chat while retaining default categories and display preferences | Confirmation names exact impact and has cancel/confirm controls |
| Migration | Upgrade a v3 database containing local ledger rows and customized display preferences | Existing ledger rows and preferences remain; the new import queue is empty and no notification source is enabled automatically | Theme, motion and currency preferences remain unchanged |
| Preferences | Toggle dark mode, centavos, reduce motion; recreate app | Chosen settings persist locally | Theme must keep readable contrast at large font; no animation is needed to understand a number |

The Rico examples are synthetic/redacted. A live notice test may use only a transaction the owner already planned or has explicitly approved; never spend money to generate a test. Android notification access is documented in the [NotificationListenerService reference](https://developer.android.com/reference/android/service/notification/NotificationListenerService); Android's local-data guidance is in its [security checklist](https://developer.android.com/privacy-and-security/security-tips). XP's [developer portal](https://dev.xpinc.com/) and [Open Finance documentation](https://developer.xpinc.com/open-finance) are recorded as the reason this debug prototype does not assume a personal direct API.

Automated tests and APK build do not replace on-device UI/visual review. Record the emulator API and owner visual sign-off separately in GOALS.md.
